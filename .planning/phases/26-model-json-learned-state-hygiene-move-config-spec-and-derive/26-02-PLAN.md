<objective>
Stop persisting category ② derived caches and recompute their values live each poll (HYG-03, HYG-04):
scheduled_test_timestamp / scheduled_test_reason / test_block_reason (scheduler output — health reads
live scheduler_manager.last_*), capacity_converged (derived from capacity_estimates CoV — health reads
live convergence_status.converged), and replacement_due (derived from soh_history regression — recompute
at read time using the CONFIGURED soh_threshold and the latest-entry capacity_ah_ref). Then prove the
strict loader still passes against a regenerated file and document the one-time deploy strip (HYG-05).

Purpose: these five keys are recomputed outputs, never learned inputs and never decision gates. Health
already sources the first four live; only replacement_due was genuinely persisted-then-read, and its
single-poll regression is cheap to recompute. The OLD persisted replacement_due was produced by
discharge_handler with threshold_soh=self.soh_threshold (= config.soh_alert) and the latest soh_history
entry's capacity_ah_ref — so the live recompute MUST use the same configured threshold and the same
baseline filter to reproduce the prior value exactly for ALL soh_alert settings (not just the 0.80
default). Removing these keys makes model.json hold only learned state and removes the
staleness/divergence risk of caching computed values on disk.

Output: a shrunk ModelState, a soh_threshold-injected compute_replacement_due() with a shared
latest-baseline helper reused by battery-health.py, scheduling/convergence writes removed, consumers
reading live values, dead tests removed, a parametrized (non-0.80) replacement_due equivalence test plus
a mixed-baseline test, strict-loader gates, and a deploy note. Depends on Plan 01 (both edit model.py and
both extend BatteryModel.__init__; sequential to avoid conflict).
</objective>
