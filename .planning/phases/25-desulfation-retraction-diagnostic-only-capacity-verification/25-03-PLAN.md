    format with sections: Title, Status (Accepted, 2026-06-03), Context, Decision, Consequences.
    Context: v3.0 shipped "active desulfation via scheduled deep discharges" on the premise that
    periodic deep discharges break up lead-sulfate crystals and extend life. That premise is
    disproven — discharge forms sulfate and charging reverses it, so a discharge-only actuator
    cannot desulfate; and the daemon has no charge-side control (verified live: CyberPower UT850
    NUT exposes only beeper/driver/load/shutdown/test.battery.start.* — no charge-voltage control).
    Cite the evidence basis: Battery University BU-804b, Power Designers Sibex, Vertiv BattCon,
    Schneider/APC, Lifeline, IEEE-1188. Decision: retract the sulfation/cycle-ROI machinery and
    reframe the scheduler to rare diagnostic capacity/SoH verification on an IEEE-1188-style annual
    cadence; the only autonomous discharge is a safety-gated diagnostic test. Consequences:
    positive (honest metrics, deadlock fixed, smaller surface) and negative/accepted (loses the
    "active care" narrative). Include the no-charge-control fact as a labeled point.
    MANDATORY Consequences bullet (operator action — addresses the reviewers' HIGH "stale model.json
    state persists" finding): state explicitly that `save()` round-trips `self.state`, so removing
    the `setdefault`/validation code does NOT purge `sulfation_history` / `roi_history` /
    `blackout_credit` / per-event `cycle_roi` already resident in a deployed
    `~/.config/ups-battery-monitor/model.json`. Per the single-host no-backward-compat policy there
    is no migration; the operator must delete the local model.json at deploy so the daemon
    regenerates a clean file from live discharges. Word it as a concrete deploy step:
    "Deploy action: `rm ~/.config/ups-battery-monitor/model.json` after upgrading to v3.2 (state
    regenerates; no migration is provided)."
    ADDITIONAL Consequences bullet (operational cost of that deploy action — mirrors Plan 02 Task 1):
    deleting model.json also discards the learned SoH / measured-capacity / LUT state, so capacity
    estimation restarts from scratch and re-warms over subsequent discharges. Record this cost as an
    explicit Consequences bullet so the operator knows the regen is not free — it is accepted under
    the no-backward-compat policy.
  </action>
