### MEDIUM

**M1 — The `segment_refs` rollover has no reserved-reference headroom, so the roll cannot write its own terminal record.**
Plan:185–187 says roll "before the next recovery segment would exceed" 64 refs, and Plan:188–192 requires the carrier to receive a durable `blackout_end` with `continued_by`. But a new segment ref is minted *because the current segment is damaged/unwritable* (`src/adapters/jsonl_event_stream.py:442-488`, `_create_continuation_segment`) — at that instant the carrier's tail is not appendable, so closing it needs a 65th segment, which `jsonl_event_capacity.py:192-193` hard-rejects with `_EventCapacityExceeded`. The byte budget got a named 2 MiB reserve; the ref budget got none. Trigger the ref rollover at ≤63 refs (or explicitly reserve one terminal continuation ref) exactly as the byte path reserves 2 MiB, and add the "roll at the reserved ref, not the hard cap" fixture alongside the existing 65th-segment test at Plan:549.

**M2 — UAT/self-test provenance is a wire invariant on recharge chains only; the blackout side has no durable field.**
Plan:585–587 makes `observation_origin`/`uat_intent_id` durable in `recharge_start`/`recharge_end`, but §4.3's blackout record/field spec (253–290) never adds provenance to `blackout_start`/`blackout_end`, and the freeze list at 346–349 (`DischargeFragmentPolicy`) omits it. Meanwhile Plan:582–584 claims the intent "marks every event whose start falls inside the active window permanently operational-only" while also allowing the intent to be closed, to expire, and to be removed after acknowledgement. Without a stamped field on the blackout record, "permanently" depends on re-reading a file that is designed to disappear — a deferred/replayed assessment (`assessment_worker.py`, `assessment_replay.py`) after intent removal can relabel induced data as natural, which is precisely the contamination §7 exists to prevent. Second, unrelated consequence of the same gap: Plan:188–193 rollover creates a successor `blackout_start` with no rule that provenance is copied, so a UAT event that rolls over silently launders its successor aggregate into natural science. Make blackout-side `observation_origin`/`uat_intent_id` a closed wire invariant, require successor/continuation records to copy it, and define the durable acknowledgement that gates intent removal as "every in-window event stamped".

**M3 — Recharge chains have sample/duration budgets but no byte bound, reintroducing the exact defect class M1/L1 fixed on the blackout side.**

But recharge samples carry the same bounded raw NUT envelope (213–214) whose per-record ceiling is 20 KiB (194–196), and recharge chains are stored under the same JSONL authority (251–252) subject to the same 64 MiB / 64-segment-ref limits. Nothing in the freeze requires `max_samples × max_physical_record_size ≤ capture-append limit`, so a long float-charge episode with large replies reaches `_EventCapacityExceeded` — an unhandled capacity exception on the "bounded indefinitely" path the plan tests at 534–536. Either add the arithmetic consistency constraint to the pre-Slice-4 freeze, or extend the same rollover/`budget_kind` machinery to recharge.
