### Medium-1 — journal-projected candidates/cohorts survive `BaselineReset` with no battery-epoch gate

Consequences: (a) Stage 4 can emit `possible_decline`/`declining` for a freshly replaced battery from pre-replacement terminal events; (b) after an operator's first accepted proposal re-populates `capacity_ah_measured`, a later automatic downward proposal could be corroborated by an old-battery event — its derived SoH passes the §3.4 predicate and the golden differential (downward only) — dragging the new battery's accepted capacity toward the old battery's value. The `None`-clause (201–202) blocks only the first automatic application, not later ones and not decline trends.
**Amendment:** one sentence in Stage 3/§5.4: candidates, cohorts, and decline trends include only events whose start record is not older than the current battery epoch (persisted `battery_install_date` / last BaselineReset timestamp); pre-replacement events remain history-only.
